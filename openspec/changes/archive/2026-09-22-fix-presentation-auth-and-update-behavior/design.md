## Context

参见 `proposal.md`。当前展示控制器在 `@Published` 的 `willSet` 通知中同步读取 store，因而会读到旧值；悬浮岛对象在切到菜单栏后仍保留会话监听，解锁回调无条件将窗口置前。Claude 重新认证分支直接调用用量接口，但没有复用常规刷新里的 429 状态转换。构建脚本用 `${SU_FEED_URL:-default}`，把“显式为空”当成“未设置”。本地成本刷新把一次共享 OpenCode 全历史扫描放在 Claude/Codex 提交路径之前。

实现必须保持 Sparkle 签名链、bundle identity、单调 semver、Claude 凭据只读原则、用量轮询最低五分钟以及持久化历史保留语义。

## Goals / Non-Goals

**Goals:**

- 让展示状态转换由新值驱动，并让窗口恢复受当前展示意图约束。
- 统一 Claude 常规刷新和重新认证的限流处理。
- 在 shell 层正确表达更新源三态，并让运行时安全处理无 feed 构建。
- 降低重复 OpenCode 扫描量与刷新关键路径等待，同时保留完整账本汇总。

**Non-Goals:**

- 不调整刷新间隔、更新签名材料、OAuth 刷新职责或发布流程。
- 不改变成本定价、去重身份或用户可见的 API 等价成本含义。
- 不引入新的后台服务或第三方依赖。

## Decisions

### 1. 展示协调器异步汇合 store 变更

订阅回调不直接同步读取 `@Published` store，而是调度到 MainActor 的下一轮再执行统一 `reconcile()`。这样模式和目标屏幕都已完成赋值，屏幕参数通知也继续走同一入口。相比在回调中传入部分新值，统一重算不会产生“新模式 + 旧目标屏幕”的混合快照。

悬浮岛控制器维护明确的 `presentationEnabled` 状态。`show()` 设置为 true，`hide()` 设置为 false；解锁恢复前检查该状态。状态属于窗口生命周期而不是读取全局模式，可避免协调器与窗口对象之间形成反向依赖。

### 2. 提取 Claude 限流状态转换

将“设置冷却截止时间、发布限流结果、安排一次冷却后重试”收敛为 MainActor 内部方法，常规刷新和重新认证共用。重新认证检测到 429 后立即结束五秒循环，结束 reauth 进行中状态，并让凭据监听在冷却结束前不发起请求。

不改变凭据读取和刷新所有权：应用仍只读 Claude 凭据，CLI 继续负责令牌刷新和写回。

### 3. shell 使用变量是否存在判断

构建脚本用 `${SU_FEED_URL+x}` 或等价分支区分未定义与已定义空值。非空时写入 `SUFeedURL`；空值构建省略该 Info.plist key，并由更新控制器根据配置决定是否启动 Sparkle。省略 key 比写入空字符串更符合“无 feed”语义，也避免 Sparkle 初始化时把空字符串当作无效 URL。

生产默认 URL、公钥和版本注入保持原值。增加一个无需完整编译即可验证生成配置的脚本级测试入口，覆盖三态。

### 4. OpenCode 首次全量、后续带重叠窗口增量

账本公开只读查询以判断某个 source 是否已经成功记录扫描。首次扫描使用 `lookbackDays: nil`；已有 OpenCode 扫描后使用现有 30 天默认窗口。30 天重叠允许迟写、修改和跨月日志被重新解析，账本的稳定 record ID 和 alias 继续负责去重。

`retain` 仍返回该 source 的全部持久化事件，因此增量扫描不会缩短月度或历史汇总，也不会因源文件轮转删除历史。查询失败时选择全量扫描，优先保证完整性。

### 5. 自有日志与共享扫描并发启动

一次刷新只创建一个共享 OpenCode task。Claude 和 Codex 各自在 detached task 内同时开始自有日志扫描，再等待共享 task，合并后独立提交。共享结果也供 MiniMax CN 和 Jev 使用。这样不重复扫描 OpenCode，并移除当前先等待共享任务再扫描自有日志的串行关系。

## Risks / Trade-offs

- [30 天窗口仍可能漏掉更早才落盘的新文件] → 文件首次出现但时间戳很旧的罕见情况由手动全量恢复工具或账本重建处理；实现测试覆盖正常迟写与轮转路径。
- [省略 `SUFeedURL` 可能影响设置页按钮状态] → 更新控制器显式暴露可用性，设置页在无 feed 构建中禁用检查动作，避免调用无配置 updater。
- [异步 reconcile 合并连续事件] → 每次都从最终 store 状态重算，连续变化可以安全收敛；测试覆盖一次切换即可生效。
- [新增账本查询与写入存在并发竞争] → 查询使用现有锁和 SQLite 只读路径；首次判断即使竞争导致重复全量扫描，也只影响性能且由账本去重保证结果正确。

## Migration Plan

不需要数据迁移。已有账本存在 OpenCode `source_scans` 记录时直接进入增量路径；没有记录的安装执行一次完整回填。正式构建继续使用现有 feed 与签名配置。回滚代码不会改变账本 schema，旧版本仍可读取现有数据。
