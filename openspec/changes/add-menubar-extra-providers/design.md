## Context

`ProviderVisibilityStore.selected` 是有序的提供方列表，原来上限为 2：第 1 个是左侧，第 2 个是右侧。灵动岛、展开面板只读取 `left` / `right`；菜单栏图标、用量抓取和提醒读取整个 `selected`。

## Goals / Non-Goals

**Goals:**
- 菜单栏模式下可以看到更多提供方，不改变灵动岛和展开面板的布局。
- 已有用户的设置原样保留，不需要迁移。

**Non-Goals:**
- 不在刘海两侧显示两个以上的提供方（刘海空间不够，而且会继续挡住系统箭头）。
- 不新增"隐藏刘海"开关：已有的"显示位置 → 菜单栏"就是这个功能，再加一个开关会互相冲突。

## Decisions

- **沿用同一个列表，上限提到 4。** 额外提供方直接追加在 `selected` 后面，而不是另开一个列表。这样抓取、提醒、菜单栏图标都自动覆盖到它们，不用改各处数据源。替代方案是单独的"菜单栏专用列表"，但需要让所有抓取逻辑同时读两份列表，改动面更大。
- **额外项只在已有两个提供方时可加。** 保证第 1、2 位始终是灵动岛的左右位置，`left` / `right` 的含义不变；`right` 改为 `count >= 2` 时取第 2 个。
- **"只用一个提供方"会清除额外项。** 与这个选项的字面意思一致，避免额外项被悄悄提升到右侧位置。
- **把额外项选入左右位置时直接交换。** 与原来"选中已占用的提供方会交换位置"的行为保持一致。

## Risks / Trade-offs

- [刘海模式下额外提供方仍会被抓取和提醒] → 超过阈值时灵动岛光晕会变色，但岛上看不到是哪个提供方。设置里的说明文字写明额外项只在菜单栏显示；影响仅限多一次抓取和提醒。
- [菜单栏图标变宽] → 四个提供方时图标较宽，可能挤进 macOS 27 的隐藏区域；这是系统的正常行为，用户可以通过箭头展开查看。
